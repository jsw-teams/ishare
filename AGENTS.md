# ishare development

- ishare is the standalone image and video publishing service at https://ishare.js.gripe. It is separate from website hosting and iask.
- Keep platform entry points under backend/cloudflare. Existing web/connect DNS/WARP code, bindings, routes and storage are outside this project and must not be changed.
- The operator manages routes. Disable workers.dev and preview URLs. Images and Stream use one resource account separate from the Worker account; account IDs are runtime Variables or Secrets; API tokens and signing keys are Secrets. Never include resource account IDs or credentials in browser configuration.
- Browser business calls use /api and validated X-Service-Action / X-Service-Resource headers. Standard /oembed supports the standard discovery protocol; canonical share, embed and media paths contain opaque application IDs.
- Authenticate publishers using GitHub's numeric user ID. Apply CSRF, ownership, upload reservations and bounded quotas before minting direct upload URLs. Do not imply verified ownership of a source website.
- Media delivery must proxy private upstream resources without redirects, provider IDs, customer subdomains or signed upstream URLs in public responses. Rewrite every HLS resource reference using authenticated opaque tickets; fail closed on unsupported manifest syntax and untrusted destinations.
- Keep upstreams private and signing keys server-side. Public delivery is shareable, not DRM. Cache hashed assets for one year, and bound media caching so deletion has a documented propagation window.
- Never claim live upload, playback, account configuration or deployment validation unless actually performed. Remove genuinely unused code and preserve unrelated user edits.
- Track image storage counts, image delivery counts, stored video seconds and delivered HLS segment seconds separately. Restrict stored images/videos and allocation frequency, not ordinary image delivery or playback; delivery dimensions are operator monitoring metrics. File bytes are upload metadata, not the media storage billing quota. Identify the operator by verified numeric GitHub ID and exempt the operator from all application quotas and shared budgets.
- Administrative quota and permission changes need user-visible reasons. Ordinary reductions use seven days of notice without deleting existing media; urgent abuse restrictions are explicit and preserve access to export, erasure and human review. Rights requests use calendar-month response deadlines; never describe technical support as certified GDPR compliance or claim erasure complete before provider cleanup.

- Canonical source is web/ishare.js.gripe. The complete directory is synchronized to the public ishare GitHub source mirror. Frontend pages use EdgePress; all backend entry points belong to backend/cloudflare. No public frontend release, cross-repository source fetching or credentials in generated assets.
- dist and .site-static are generated. Source UI fragments are in plugins/application; browser logic lives in static/ishare. Keep nav/footer, language switching, keyboard focus and immutable asset hashes.

- The operator Worker deploys from jsw-teams/web, root ishare.js.gripe. The public jsw-teams/ishare repository is a source mirror for distribution, not the operator deployment source. Keep Secrets only in Cloudflare.

- Derive business origins from the routed request URL, never forwarded-host headers or required origin variables. Public get/oEmbed metadata supports credential-free CORS; private reads and writes keep same-origin and CSRF checks. One MEDIA_API_TOKEN accesses the shared Images/Stream resource account.
- Operator build root is /ishare.js.gripe in jsw-teams/web. This site enables no general media-platform consent services. Other web/EdgePress sites preset only X and YouTube; do not restore broad platform lists.

- Official names are ishare in English and 爱分享/愛分享 in Chinese. Keep names separate by locale. Homepage is an opt-in public post feed; My shares holds the text-first composer, multiple attachments and owned history. Never auto-enroll legacy content in the feed.
- English is the default locale at the site root; Traditional and Simplified Chinese use /zh-TW/ and /zh-CN/. Keep config.yml, edgepress.config.mjs, language dictionaries, localized links and source mirror synchronized when changing locale defaults.
- Quotas are managed online by the verified GitHub operator and persisted in SQLite, not MAX_/QUOTA_ variables. Default changes preserve existing user policies; ordinary shared reductions receive notice. No extra video-byte quota beyond provider limits.
- STREAM_ACCOUNT_ID is shared by Images/Stream. Remove obsolete IMAGES_ACCOUNT_ID and STREAM_CUSTOMER_CODE configuration; do not restore aliases. Discover signed playback addresses using the authenticated API.

- Administration lives on its own native /admin/ Pages route; My shares contains publishing/history and graphical quota usage. Personal data and rights live in the native /profile/ personal center. Show its link only to authorized administrators and enforce authorization in the backend. Keep the composer to text and attachments without source fields or routine technical notices. Preserve legacy source metadata for existing records, but reject it on new write APIs. Simplify quota inputs without overwriting unedited policy fields. Fetch GitHub avatars through fixed /api header actions, never arbitrary avatar URLs or an additional consent platform.

- Account navigation lives in the avatar dropdown: personal center, administrator-only management and logout. Preserve keyboard support and clear selected/loading/saved feedback. Public /u/<numeric GitHub ID> profiles expose display name, plain-text bio and published post history; the homepage checkbox affects only homepage inclusion. Never expose drafts, deleted posts, erasing accounts or sharing-restricted posts in public history. Private profile edits preserve verified GitHub identity and require same-origin authentication and CSRF. Exports include the profile; completed erasure removes it. Profiles are additive SQLite tables in the existing ShareStore namespace.

- Use the current Images API response field `meta` to verify the stored application ID; the direct-upload request form field is `metadata`. Do not add obsolete response aliases. Upload progress must reflect real transferred bytes, distinguish provider confirmation from post publication and cancel failed attempts by removing their newly allocated attachments. Use a centered upload modal with cancel-and-cleanup and explicit dismissal; expected processing is not a generic fatal error.

- Media failures must show accessible, localized placeholders and explicit retries on share pages, embeds and preview cards. Missing upstream resources return sanitized uncached errors; never erase production records or release quota merely because delivery fails. All simulated upload tests use isolated in-memory databases and browser mocks, with final cleanup; never create test posts on production.
- Private page bootstrap uses fixed /api headers and one authorized DO snapshot, never public caching or persistent browser storage. Coalesce only in-flight identical reads, preserve writes and abort semantics, fetch fresh data after mutations, and lazily load hidden administrative sections.

- No cron or scheduled handler. Schedule a Durable Object alarm only when pending allocation/removal/erasure work exists; cancel it when the queue is empty. Preserve the deployed storage identity and migration history; overwrite the existing Worker rather than creating versioned namespaces. Failed/duplicate upload cleanup must match exact creator and application metadata, never filenames alone, and must not remove published posts. Restriction appeals live on /appeal/, while other data rights remain in /profile/.

Expired sessions, OAuth states, counters and minimal accounting/audit rows also use their next retention deadline as a one-time alarm; never replace this with an idle periodic cron.

- Image and video attachments belong to one post, with videos first and images afterwards, stable within each kind. Do not generate covers in the browser. Fetch one fixed server-generated Stream cover and persist its JPEG bytes for reuse; delete the saved cover with its media. If browser metadata is unavailable, reserve a bounded video duration under the account's remaining allowance; Stream enforces that duration and publication replaces the reservation with the actual duration. New TUS grants start at offset zero; use HEAD only to recover interrupted PATCH requests. Cleanup feedback must preserve the failed attachment, phase and friendly reason. Diagnostics may contain known error codes and numeric HTTP statuses, never credentials, upload capabilities or upstream playback addresses.

- Stream TUS creator uploads currently return upload.cloudflarestream.com in Location. Accept that exact HTTPS upload origin in the shared validator and CSP; do not retain the obsolete videodelivery upload origin or broaden to arbitrary customer playback domains. Stream resource account IDs come from STREAM_ACCOUNT_ID, video IDs from stream-media-id, and customer playback addresses from the authenticated REST API. Never hardcode resource account or customer IDs.

- Posts have only caption and attachments, without a separate title field. Migrate the existing posts table in place; retain file labels for media alt text and exports. Feed/profile cards request only the first attachment. Detail/embed galleries mount only the selected attachment and dispose video playback on navigation. Public profiles and account menus display the chosen name without GitHub handles or numeric identity labels. Expected provider processing returns HTTP 202, not an error. Deletion revokes publication immediately, hides the item from normal history, and completes provider cleanup with bounded parallelism; retain quota accounting until upstream deletion succeeds. Stream DELETE has an empty successful response, as documented; do not require a JSON envelope.

- Use the standalone media-viewer library for player controls, gallery lifecycle and image zoom; do not restore duplicate control implementations. Keep mobile controls clickable, local icons, explicit playback and disposal. Default image delivery uses private signed 640/1280/2048 variants and format-aware caching. Original image bytes are requested only on opening the lightbox or saving. No save overlay on content pictures. HLS references may use JWT paths or independently signed provider-ID segments on the same validated host; preserve their signature namespaces and ticket ownership. Verify actual playback and image opening without production uploads or authenticated browser cookies.

- Use the committed Lucide SVG module for quota, upload and gallery icons; regenerate with npm run icons:sync when changing the selected set, retain its ISC notice, and do not ship an entire icon runtime. Remove redundant manual refresh controls; load admin data when its tab is selected and invalidate it after writes.
- Keep gallery geometry stable before mounting the player and when switching attachments. Reserve loading/status space. Run mobile light/dark axe and CLS fixtures, including signed-in screens; test portrait and landscape shared viewer focus and touch targets. Tests must remain isolated from production writes.

- Post pictures remain optimized and lazy; only clicking opens the original. The lightbox must not display the optimized preview while claiming to load the original. Keep current/total video time visible at mobile container widths. Preload the first selected video's cover without loading playback segments. Generate its cover at one second (first frame for videos shorter than a second), persist and reuse it; preserve explicitly supplied covers. Refresh legacy generated covers once, without changing storage identity or media records.
- Player colors follow page theme variables. Keep HLS rate-aware ABR and bounded buffering in the shared media-viewer component, and avoid restarting an already active loader. Resolve cold playback metadata and signatures concurrently, reuse the private cache, and verify startup/2x playback without production uploads.
- Adapt preview renditions to optional network/data-saving hints while keeping original-image URLs unchanged. Put attachment counts and video badges below pictures. Bound upstream header waits without aborting a valid slow body after a fixed deadline; retain client cancellation, streaming and fresh deletion checks. Test transfers longer than the header timeout with isolated fixtures.
